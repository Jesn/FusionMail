# 批量导入自定义分隔符功能

## 功能概述

在批量导入短效邮箱时，用户现在可以自定义字段分隔符，不再局限于默认的 `----`。

## 使用场景

### 默认分隔符（----）

**标准格式**：
```
user1@outlook.com----pass1----refresh_token_1----client_id_1
user2@outlook.com----pass2----refresh_token_2----client_id_2
```

### 自定义分隔符

**场景 1：使用逗号分隔**
```
分隔符设置：,
账号格式：user1@outlook.com,pass1,refresh_token_1,client_id_1
```

**场景 2：使用制表符分隔**
```
分隔符设置：	（Tab键）
账号格式：user1@outlook.com	pass1	refresh_token_1	client_id_1
```

**场景 3：使用竖线分隔**
```
分隔符设置：|
账号格式：user1@outlook.com|pass1|refresh_token_1|client_id_1
```

**场景 4：使用自定义字符串**
```
分隔符设置：::
账号格式：user1@outlook.com::pass1::refresh_token_1::client_id_1
```

## 功能特点

### 1. 灵活的分隔符设置

- ✅ 支持任意字符或字符串作为分隔符
- ✅ 默认值为 `----`（保持向后兼容）
- ✅ 可以随时修改分隔符
- ✅ 提供"重置为默认"按钮

### 2. 实时格式提示

- 📝 格式说明会根据当前分隔符动态更新
- 📝 输入框占位符显示当前分隔符的示例
- 📝 实时显示识别到的账号数量

### 3. 智能识别

- 🔍 根据设置的分隔符自动识别账号
- 🔍 只统计包含分隔符的有效行
- 🔍 自动过滤空行和无效行

### 4. 后端兼容

- 🔄 前端自动将自定义分隔符转换为标准格式（`----`）
- 🔄 后端无需修改，保持原有逻辑
- 🔄 确保数据格式的一致性

## 使用方法

### 步骤 1：打开批量导入

1. 点击"添加账户"按钮
2. 选择邮箱提供商：Outlook/Hotmail
3. 选择协议：批量导入（短效邮箱）

### 步骤 2：设置分隔符（可选）

**使用默认分隔符**：
- 不需要任何操作，直接使用 `----`

**使用自定义分隔符**：
1. 在"分隔符"输入框中输入你想要的分隔符
2. 例如：`,`、`|`、`::` 等
3. 格式说明会自动更新显示新的分隔符

### 步骤 3：粘贴账号

在"账号列表"文本框中粘贴账号字符串，使用你设置的分隔符：

```
user1@outlook.com,pass1,refresh_token_1,client_id_1
user2@outlook.com,pass2,refresh_token_2,client_id_2
user3@outlook.com,pass3,refresh_token_3,client_id_3
```

### 步骤 4：验证和导入

1. 查看"已识别 X 个账号"提示，确认识别正确
2. 点击"开始导入"按钮
3. 等待导入完成
4. 查看导入结果

## 技术实现

### 前端处理流程

```typescript
// 1. 用户输入账号（使用自定义分隔符）
const input = "user@outlook.com,pass,token,client_id";

// 2. 识别账号（使用自定义分隔符）
const accounts = input
  .split('\n')
  .filter(line => line.includes(batchSeparator));

// 3. 转换为标准格式（后端期望的格式）
const normalizedAccounts = accounts.map(line => {
  if (batchSeparator === '----') {
    return line; // 已经是标准格式
  }
  // 替换自定义分隔符为标准分隔符
  return line.split(batchSeparator).join('----');
});

// 4. 发送到后端
await accountService.batchImport(normalizedAccounts);
```

### 状态管理

```typescript
// 分隔符状态
const [batchSeparator, setBatchSeparator] = useState('----');

// 重置逻辑
useEffect(() => {
  // 切换协议或关闭对话框时重置
  setBatchSeparator('----');
}, [formData.protocol, open]);
```

### 验证逻辑

// 验证分隔符
if (!batchSeparator || batchSeparator.trim() === '') {

## 常见问题

### Q1: 分隔符可以是多个字符吗？

**A**: 可以！分隔符可以是任意字符串，例如：
- 单个字符：`,`、`|`、`;`
- 多个字符：`--`、`::`、`||`
- 特殊字符：`\t`（制表符）、` `（空格）

### Q2: 如果账号中包含分隔符怎么办？

**A**: 建议选择一个不会出现在账号数据中的分隔符。例如：
- ❌ 不推荐：`,`（邮箱地址可能包含逗号）
- ❌ 不推荐：`.`（邮箱地址包含点号）
- ✅ 推荐：`----`、`||`、`::`（不太可能出现在数据中）

### Q3: 修改分隔符后，之前的账号还能识别吗？

**A**: 不能。修改分隔符后，只会识别使用新分隔符的账号。建议：
1. 先设置好分隔符
2. 再粘贴账号数据
3. 或者使用"重置为默认"按钮恢复

### Q4: 后端需要修改吗？

**A**: 不需要！前端会自动将自定义分隔符转换为后端期望的标准格式（`----`）。

### Q5: 分隔符会被保存吗？

**A**: 不会。每次打开对话框都会重置为默认的 `----`。这是为了避免混淆。

## 最佳实践

### 1. 选择合适的分隔符

**推荐的分隔符**：
- `----`（默认，最安全）
- `||`（双竖线）
- `::`（双冒号）
- `\t`（制表符，适合从 Excel 复制）

**不推荐的分隔符**：
- `,`（可能与数据冲突）
- `.`（邮箱地址包含点号）
- `@`（邮箱地址包含 @）
- 空格（容易混淆）

### 2. 数据准备

**从 Excel 导出**：
1. 在 Excel 中准备数据（4列：邮箱、密码、token、client_id）
2. 选择数据并复制
3. 设置分隔符为 `\t`（制表符）
4. 粘贴到批量导入框

**从文本文件**：
1. 使用文本编辑器准备数据
2. 选择一个明确的分隔符（如 `----`）
3. 确保每行格式一致
4. 复制粘贴到批量导入框

### 3. 验证数据

导入前检查：
- ✅ 分隔符设置正确
- ✅ "已识别 X 个账号"数量正确
- ✅ 格式说明与实际数据匹配
- ✅ 没有空行或格式错误的行
